  → 06 授权认证 + 07 账号

分批怎么切（一个模块几接口一起）
阶段 0 — 基础设施
响应、异常、鉴权骨架、日志、健康检查（如 GET /health）、空 api_router 能跑通。

阶段 1 — 06 + 07（约 8 个）
OAuth 可先 stub；优先：密码登录、登出、获取/改账号信息。没登录后续都测不了。

阶段 2 — 03 上传（2 个）
文件/图片上传（接 MinIO）。应用 icon、知识库文档都依赖。

阶段 3 — 01 应用 · CRUD（约 6 个：1.1–1.6）
详情、创建、删除、列表、复制、改基础信息。先能出「工作台应用列表」。

阶段 4 — 04 知识库 · 基础（约 4.1–4.5 + 文档列表 CRUD 一批）
库 CRUD、详情；文档/片段可第二批。召回测试、批处理进度放到库+向量链路就绪后。

阶段 5 — 02 插件
先做只读：分类、内置列表、详情、icon；再做自定义 API Tool CRUD + OpenAPI 校验。

阶段 6 — 01 应用 · 配置与发布（1.7–1.10、1.15–1.20）
草稿读写、发布/取消/历史/回退/WebApp token。调试对话（1.11–1.14）放到会话能力一起做。

阶段 7 — 05 会话 + 01 调试流式
会话列表/消息/删改/置顶；再做 SSE 对话与 stop（最难，单独成批）。

阶段 8 — 11 工作流
CRUD + draft-graph + publish；debug 流式可后置。

阶段 9 — 09 OpenAPI
API Key CRUD + /openapi/chat。

阶段 10 — 08 + 10
优化 Prompt、建议问题、应用广场；依赖已有应用能力，可穿插在 3–6 之间做。

三、和你目标的对应关系
现在：基础设施 + main.py 统一启动 — 正确，先做。
接着：按上表模块分批迁；每批 = 该模块一组接口的 router + schema + service。
先不做：Flask 模型里那些 @property 查库逻辑，等对应模块 Service 再补。
